# v3.61 Reliability Pilot — Real Athlete & Device Sign-Off

**Status: pending, not performed.** Do not publish or distribute as consumer-ready on the basis of CI alone. Use consented test data, do not put any real athlete exports, personal details, credentials or screenshots of identifiable training in a public GitHub issue.

## Before inviting athletes

1. Verify the exact tested build (v3.61.0, native build 33405), Android/iOS compilation and browser regression results. Record the commit SHA and source of the installed APK/PWA. Debug-signing is not store signing.
2. Prepare a disposable test installation and a verified backup copy. Never test migration on an athlete's only saved history. Check available device storage and export access before changing data.
3. Define a rollback decision: stop the pilot immediately for data loss, unexplained kg/lb changes, records entering the wrong account, corrupted backups or any action that silently changes a program, log or medical decision.

## Device recovery (both Android and iPhone)

- [ ] Import a copy of a legacy backup; compare exact workout/exercise identities, names, all sets, PR values, revision histories, Calendar sessions and display units before/after app force-close and restart.
- [ ] Attempt to import a backup in which one PR weight or exercise name differs but IDs and counts stay fixed. Confirm the preflight blocks replacement and newer local work remains intact.
- [ ] Leave the import review open, record a new workout, and try to confirm the stale import. It must ask for a new preview, not overwrite the new workout.
- [ ] Log multiple offline workouts, including one with corrected sets and RPE; force-close during an unfinished draft and verify restart behavior. Repeat under simulated low-space or failed-write conditions on a disposable device.
- [ ] Export to device Files, independently verify the backup, restore onto a separate clean test installation, and check kg↔lb presentation while canonical stored kg remains unchanged.

## Coach & first-workout comprehension (3–5 consenting athletes recommended)

- [ ] Ask Coach for a dumbbell-and-bench equipment update; cancel once, then Save explicitly. Confirm all main/accessory equipment changes shown in review and no historical workout changes.
- [ ] Ask for a 20-week meet prep, three days/week, 60 minutes, full gym; identify the event date, five-stage timeline, limits and separate Save/schedule decisions without assistance.
- [ ] For someone with no prior workout logs, open the daily builder's step-by-step guide. Can they choose movements, explain per-hand versus total loads, find “I don’t know my starting weight,” and interpret RPE 6/7/8 without having a weight guessed for them?
- [ ] Confirm that navigation/actions are not logged as completed training and unsupported or medical/injury questions do not silently produce a prescription.
- [ ] Collect anonymized usability feedback: where they hesitated, number of steps abandoned, mislabeled controls, confusing terms, and whether they would trust another backup/restore.

## Evidence and go/no-go record

For each execution, record: date, pseudonymous tester, device model, OS, release/build, commit SHA, test ID, pass/fail, expected versus observed behavior, reproduction instructions, backup fingerprint status, and any blocked issue. Keep private data in an access-controlled testing record.

Acceptance requires no unresolved critical data-loss/privacy/safety issues; successful recovery on both physical platforms; understandable first-time flow; explicit approval boundaries upheld; no blocking CI failures; and a separate human sign-off for hosting, signing and store distribution. Preserve the existing [Phase 6 beta gates](phase6-athlete-beta-acceptance.md) and [v3.60 pilot](unified-v3.60-pilot.md); this checklist supplements them.
