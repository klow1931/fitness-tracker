# Loadnote v3.3.0

Decisions and both views of Coach share an offline reference library. Explore coaching references opens search, source coverage, upcoming-plan comparisons and optional local AI. Coach can explain Louie Simmons/Westside conjugate principles, distinguish heavy and speed work, discuss accessory priorities and explain phases with linked sources. Follow-up questions retain the most recent user topic; a new topic breaks that context.

The fifth edition of NSCA's Essentials of Strength Training and Conditioning and Louie Simmons' Westside Barbell Book of Methods are reference listings. Neither complete book is imported, redistributed or claimed as model training data. NSCA's accessible preparatory-period excerpt is explicitly identified as fourth-edition material. Public Westside articles citing Book of Methods support the original summaries. Coaching methodology is labelled separately from a research position stand. Book references do not imply endorsement by their publishers.

Referenced phase-preview reviews use saved experience, availability, symptoms and exercise exclusions. A conjugate comparison explains why a general linear/wave plan is not automatically a full Westside template. Training targets remain governed by the existing reviewed builders and approval paths. Personalization uses explicit saved data; repeated exercise edits remain descriptive until the user confirms a preference, and logs do not establish causality.

Optional local AI is off by default and enabled only for the current app session after explicit download consent. WebLLM 0.2.85 selects a small instruction model from its published configuration, checks WebGPU availability, and runs educational and instruction-conflict checks on the device before enabling. Runtime/model files are downloaded from external hosts; prompts are supplied only to the local engine. No programming profile, intake, workout log or chat history is passed to that engine. Questions can still contain whatever the user directly types.

Generated explanations are experimental, labelled, and followed by the canonical guidance and actual references. Output validation rejects malformed JSON, numbers, markup, links and several unsafe claims; it does not prove that all generated statements are accurate. These explanations cannot invoke app actions or change training. Unsupported GPUs, download failures, failed device checks, invalid output and generation failures retain referenced local answers. Turning off unloads the model; it does not delete browser caches. Initial downloads and browser cache retention mean offline AI availability cannot be guaranteed.

Validation uses deterministic retrieval and planning fixtures, a mocked local inference adapter, and desktop/mobile browser smoke coverage. Device checks execute with the actual model when the user enables it. Physical iPhone memory, performance, battery use and coaching accuracy still require device acceptance testing; this release does not claim full on-device validation or a medically validated model.

No data-schema change is required. Existing profiles, programming edits, backups and native local guidance remain compatible. Native release metadata and the web app/cache version are aligned to 3.3.0.
