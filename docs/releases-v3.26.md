# Loadnote v3.26.0 — Guided programming and recoverable edits

## Six usability improvements

1. **Guided setup.** Help me get started opens goal, schedule, equipment and review steps. The main strength/meet program route opens schedule/style, chosen maxes, then accessories/review. Back keeps values. Show all fields remains available; advanced builders retain their full-form entry and offer guided steps. Hypertrophy and sport forms offer the same navigation without relaxing their distinct technical/review requirements.
2. **Plain language.** Phase setup and program overviews explain building volume, heavier lifting, peak, taper and deload. Training-max help sits beside the lift fields; an expandable glossary explains RPE, exposures and loading styles. Unknown maxes remain blank; manual logging still needs no max.
3. **Program status.** Draft proposals, reviewed records, scheduled plans, linked execution and finished plans share a status path. Calendar time passing does not turn unconfirmed work into completion. Cancellation is explicit. Strength/meet closure still uses existing results/handoff requirements.
4. **One readable review.** Current choices appear together, with existing suggestions and reasons expandable underneath. Generated previews answer five questions: training days, estimated session lengths, first workout, phase changes and the effect of confirmation. Saving a reviewed plan and scheduling it are separate actions; neither fabricates actual work or meet attempts.
5. **Actionable errors.** Native field errors and common domain errors reveal the relevant step/details, focus and describe the field, and retain entered answers. Unknown errors stay visible in the existing form alert rather than being assigned to a guessed field. Guided day-count/max checks run before advancing.
6. **Undo.** Logger set/exercise removals retain actual field values and completion. Unsaved hypertrophy/sport slot removals retain entered settings. One pending Undo per surface is offered until replaced or dismissed; logger Undo expires when the workout is cleared, replaced or saved. These transient actions do not survive reload. Calendar Undo persists a new date/status revision, never deletes history, and refuses a later revision, recorded workout or linked open draft. Persistence failures leave current state intact and the Undo retryable.

## Data and limitations

No training schema or prescription rules changed. Guided form answers are retained while the form remains open, not saved as a new cross-device draft. Safety, equipment, identity, dose, evidence and quality gates remain authoritative. Form defaults and estimates are not a personalized prescription or a guarantee of session duration. Training-max percentages still use explicitly chosen maxes.

## Acceptance

Test goal setup through program review, explicit scheduling and first actual workout on desktop and phone. Verify Back, full-field escape, missing/unknown fields, failed persistence, matching status, 320px/large text in both themes, exact Undo restoration, stale Calendar guards and refresh after a persisted Undo. Native compilation/emulator checks do not substitute for physical-device acceptance.
