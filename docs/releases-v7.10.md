# Loadnote v7.10.0 — Clearer Home and workout flow

Version7.10.0 · unsigned native build40000 · schema34.

Simple Home keeps the existing guarded Today/start/resume action first, followed by a compact rolling seven-day summary and one chosen goal. The mode switch remains two-way and44px minimum but uses a compact header rather than a full-size card. Duplicate first-workout wording is removed from the weekly summary; first-week logging/resume tips use a native disclosure while unique saved-plan/repeat/history handoffs remain visible. Full Home and Calendar remain available.

Home's chosen goal delegates to the existing goal-progress engine. Workout-count attendance and estimated-strength targets remain distinct; older goals without captured baselines show no invented percentage. Start/Now/Finish values use existing display-unit conversion; changing the displayed goal never edits the goal or history. Manage goals opens the established Coach goal editor.

Progress leads with exercises and goals. Users can pin any logged exercise/tracking identity for direct return to its existing bar/line graph. Deleted or no-longer-logged identities disappear from quick links without fabricating records or deleting the preference. Pins and the selected Home goal are presentation preferences only, under loadnote.ui-flow.v1, saved on this device with bounded normalization and honest storage-failure rollback. They do not change training collections or require data migration.

Current-set target/last-confirmed information uses a responsive layout; existing load/reps/RPE, completion, rest return, undo and durable save engines remain authoritative. Workout tips become an expandable disclosure after execution begins and can still be opened, dismissed or replayed from Profile. The inline Help with this set action opens the existing contextual Coach and prefills a question only when the composer is empty; it never sends automatically. During a genuinely reduced numeric-keyboard viewport the floating launcher is hidden, while controls stay in document flow. Mobile numeric inputs use16px text and44px targets.

Architecture: ui-flow.js is a small presentation preference/goal-selection model; home-goal-ui.js renders the shared goal projection. Existing progress-ui.js, Simple Home, beginner guidance, execution and viewport modules are incrementally extended. No programming/adaptation, unit storage, actual RPE, e1RM/training-max, mesocycle/fatigue, workout history or account/cloud policy changes. Offline Coach and optional research are unchanged; both added modules are offline assets.

Validation: new Node tests cover preference normalization/reload/failure, exact tracking identity, missing/deleted identities, count versus unknown-baseline strength and immutable history. New touch-browser journeys cover one-action Home/resume, goal selection/reload/failure, pinned bar/line graphs, lb/RPE draft recovery, unsent contextual Coach, and320px/enlarged-text/light-dark/reduced-keyboard layout. Existing first-week tests open the intentional disclosure before exercising original actions; no data/effort/history assertions removed. Both recurring mobile profiles select the new cases. Exact full Node/static/release/browser/native/emulator/security evidence and any limitations are recorded in PR/tracker, not assumed here.
