# Loadnote v3.20.0 — First-week guidance and intake recovery

Athlete intake is now actionable before a programming profile exists. Profile opens a named prerequisite dialog, explains why setup is needed, and continues to intake only after an explicitly saved, durable training setup. Cancelling or a failed save does not create intake, discard a workout or approve targets. Existing Profile and Decisions entry points remain available after setup.

Home's getting-started steps have direct review actions and an optional intake shortcut. The supported Program planner still owns program selection, dose review and separate Calendar scheduling; no plan is generated or scheduled by opening the hub.

Home, Coach and Decisions share a compact current-week disclosure. It separates recorded workouts, recorded strength sets, unknown effort, linked session logs, unconfirmed past dates, upcoming work, explicitly skipped and cancelled sessions. Duplicate links and changed Calendar revisions are flagged. A log is not proof that all targets were met, and an unconfirmed date is not automatically a missed workout. Corrected current records replace earlier observations; future-dated evidence is excluded.

A saved-session briefing shows the next scheduled session's purpose and opens the existing exact-target explanation. Multiple sessions require selection rather than a merged prescription. Session constraints still route through reviewed time/preferences, fresh-target exercise edits and Calendar changes. These are not new dose-equivalent alternatives or automatic progression.

CI adds first-week and intake button regression tests in desktop/mobile Chromium and mobile WebKit. WebKit emulation does not establish physical iPhone, standalone Safari storage, Android WebView, native background or device-model performance.

Version 3.20.0/build 32000, schema 32 unchanged. Android/Google Play is the first distribution priority; iPhone Home Screen testing continues while paid Apple distribution is deferred. Packages remain unsigned development/local-only. Store accounts, signing, physical-device acceptance and privacy declarations are not provisioned by this update.
