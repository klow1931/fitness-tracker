# Loadnote v3.4.0

Coach Companion can use the optional WebLLM model as a local conversation engine, beyond the referenced educational explanations introduced in v3.3. It supports encouragement, training discussion and bounded follow-ups. Full Coach and the floating Companion share the model and their session-only conversation.

Open Local AI in Companion or Explore coaching references in Decisions. Download consent enables the model after the existing device checks. A separate checkbox permits the local model to use a compact training summary and recent conversation. Apply the settings again to revoke context consent; Turn off unloads the model. These settings reset after reloading the app. Browser caches may retain downloaded model files.

The summary is rebuilt on every question from saved setup, structured intake concern status, goals, weekly logs and effort coverage, current task, upcoming movements, and confirmed exercise preferences. Raw workout records, contact fields, profile notes, free-text injury history, injury notes and clinician instructions are omitted. Goal and movement labels and recent messages are still user-provided text. They are treated as untrusted data. Unknown or invalid context stays unknown. Repeated edits do not become confirmed preferences automatically, and new data does not retrain model weights.

Inference stays in the device's browser runtime. While local conversation mode is selected, Companion does not call Online Coach, including when local inference is unavailable or a reply is rejected. Model/runtime downloads still need external hosts and internet. The reference-only option remains available without training-context consent. Selecting local conversation also ends an active online realtime voice session and blocks new realtime voice starts. Pending voice starts are cancelled before microphone/connection continuation. This release adds local text conversation, not offline speech recognition or realtime local voice. Turning off local conversation restores the existing routing policy, which can use Online Coach if signed in.

Injury, treatment, sensitive-health, exact-dose, target and training-change questions bypass generated conversation. Deterministic guidance, source links and existing Decisions approvals remain responsible for those workflows. Generated text is labelled experimental, carries no executable actions, and is followed by canonical guidance when available. Output validation rejects malformed JSON, numerical targets, markup, links and selected unsafe claims. These checks and the two model-enable probes are limited safeguards, not proof of factual accuracy or a medically validated coach. All generated statements still need user judgment.

A conversational request times out after thirty seconds, interrupts generation and falls back to built-in guidance. It retains the private routing selection until explicitly disabled; late results and revoked consent cannot render a model reply. Clearing conversation removes both views' in-memory transcript. Nothing is persisted as model memory or a conversation archive by this feature.

The model requires compatible WebGPU and sufficient memory. Native webviews and older devices may not support it. An enabled pretrained model with Loadnote's context and policy is not a newly trained proprietary model. Actual iPhone compatibility, speed, memory, battery use and coaching accuracy require physical-device acceptance testing. First-use downloads and browser cache eviction mean offline model availability is not guaranteed. The reviewed local coach continues to work without it.

Validation includes context minimization, fresh-data changes, explicit consent, prompt-injection boundaries, sensitive-topic bypass, failure and timeout routing, late-response revocation, and desktop/mobile shared-conversation tests using a mocked runtime. Native and web version metadata are aligned to v3.4.0. No data-schema migration is needed.
