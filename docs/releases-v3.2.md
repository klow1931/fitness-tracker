# Loadnote v3.2.0

Athlete intake adds revisioned training history, past and current concerns, laterality, reported clinician limits and training priorities. Profile and Decisions expose the questionnaire; both Coach views can open it. Existing profiles remain compatible and unknown history is not invented.

Current symptom reports hold generated programming and automated increases. Exact aggravating movement identities block new selections. General Coach education explains reported concerns without diagnosing dysfunction or prescribing rehabilitation. Professional activity instructions remain visible context; free text is not an executable clinical protocol.

The session editor previews removing, replacing or adding strength/cardio movements in current or future unperformed Calendar sessions. Changes to primary work need explicit acknowledgement. New movements require fresh targets; loads stay stored in kg. Completed history and frozen source programs remain intact. Technical sport protocols, peak/event additions and replacements use their existing dedicated review paths.

Cardio planning previews 1–20 weeks at a stable athlete-selected duration and easy/moderate intensity, with no automatic progression or inferred heart-rate zone. It checks available weekdays, session duration, planned/logged sessions and reported practice/competition/event dates. Combined same-day cardio can be added through the session editor; athletes still review total session workload.

Every edit records its stated reason. Learning shows descriptive edit history and exact-revision linked logs. Repeated preference or equipment removals from distinct sessions can become confirmed future exclusions. Symptom edits do not infer preferences, successful rehabilitation or causality.

Schema 32 preserves intake inside existing programming-profile backup and sync revisions. Structured intake is removed from automatic online Coach request context; directly typed messages and existing chat history still use the existing consent flow. Approval rechecks current profiles, prescriptions and movement identities, and UI data changes only after a successful durable save.
