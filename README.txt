FitTrack (web) — quick start for testers
========================================
Version: web v25

What this is
------------
A local-first fitness tracker in your browser:
workouts (strength + cardio), nutrition, PRs, calendar,
body measurements, progress photos, technique self-check (checklist),
and AI coach (built-in + optional your own API key).

How to open
-----------
1. Unzip the folder (or open your GitHub Pages URL).
2. If using files: double-click index.html
   - Best: Chrome or Edge
   - Safari: File → Open File… then choose index.html
3. Prefer a hosted URL (GitHub Pages) on phones — file:// can be flaky.
4. Allow storage if the browser asks.

First things to try
-------------------
• Home → Start here (3 big buttons)
• Train → Log only (History / Templates are separate tabs)
• Food → Today + Add food (Library / History optional)
• Coach → Insights or Chat first (Programs / API optional)
• More → Measures, Form (self-check checklist), Photos, Tools
• Tools → Load demo data (optional) or Export JSON backup

Form tab (technique)
--------------------
• Self-check checklist only — not an automatic video breakdown.
• Video is for playback while you mark cues; the app does not analyze form with AI.
• Only checklist answers and notes are saved (video is not stored).

Coach disclaimer
----------------
• The AI Coach is not a doctor, physical therapist, dietitian, or licensed
  medical professional.
• Insights, chat, deload ideas, and programs are general fitness
  recommendations only — not medical advice, diagnosis, or treatment.

Privacy
-------
• Your logs stay in THIS browser on THIS device (IndexedDB / localStorage).
• Optional AI API keys stay in the browser and are NOT included in JSON backups.
• Keys are only sent to the AI provider you configure when API chat is enabled.
• GitHub only hosts the app files — not other people’s workout data.
• Clearing browser site data will erase local history — export backups.

Notes / limits
--------------
• Each browser/profile has its own data (Chrome ≠ Edge).
• Opening via file:// is fine for desktop testing; phone use works better
  on a real https:// link (e.g. GitHub Pages).
• This is a prototype for feedback.
